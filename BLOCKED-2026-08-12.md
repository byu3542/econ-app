## What G7 flagged, and why it is not this run

```
[FAIL] G7  on a branch; no force/amend/rebase
        - reflog shows a hard reset in this run: reset: moving to 97c5d49
```

That entry is `HEAD@{21}`, `97c5d49`, timestamped **2026-08-12 10:42:05 -0600**.
This run started at **16:02:18** (`checkout: moving from main to
fix/recreate-tab-clobber`, `HEAD@{2}`). The reset is 19 commits below my base
and five hours before the branch existed. I ran no reset, amend, rebase, or
force-push.

**Cause** — `gate_g7`, `scripts/merge_gate.py:107-120`:

```python
code, out, _ = _git(repo, "reflog", "--format=%gs", "-40")
...
    if base[:7] in entry:      # entry is the reflog SUBJECT
        base_seen = True
```

`%gs` is the reflog subject: `commit: <message>`, `checkout: moving from X to Y`,
`merge <branch>: Fast-forward`. None of those carry a sha, so `base_seen` never
becomes true, the `break` never fires, and the scan walks all 40 entries into
pre-run history. The "in this run" scoping is therefore inoperative for every
caller — any repo whose last 40 reflog entries contain one old reset, amend, or
rebase fails G7 permanently, regardless of what the run did. It is a false
positive that gets *worse* the healthier the repo's recent history is (this repo
will not age that entry out for another 19 reflog entries).

## What I would have chosen

One-line fix, smallest thing that restores the intended scoping — ask git for
the sha alongside the subject and match on that:

```python
code, out, _ = _git(repo, "reflog", "--format=%H|%gs", "-40")
...
for entry in out.splitlines():
    sha, _, subject = entry.partition("|")
    if sha.startswith(base[:7]) or base[:7] in subject:
        base_seen = True
    low = subject.lower()
    ...
```

`%H` on a reflog entry is the commit the ref pointed at *after* that entry, so
the base commit's own entry matches and the scan stops there — which is what the
`break` was written to do. Keeping the `base[:7] in subject` test too costs
nothing and preserves the current behaviour for entries that do name a sha
(`reset: moving to <sha>`).

Two properties worth keeping in whatever fix lands:

1. **A reflog with fewer than 40 entries, or a base that has aged out, must still
   fail closed** — if `base_seen` is never set, the current code already scans
   everything, which is the safe direction. Don't invert that.
2. **No skip flag.** The module docstring is right that a bypass an agent can
   reach is a gate that does not exist. This should be fixed at the detection,
   not exposed as `--no-g7`.

I did not verify the fix against `merge_gate.py`'s in-process tests — those live
under `app/src/test/**`-equivalent guardrails I may not edit either. Whoever
takes this should run them.
