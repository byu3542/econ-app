# MS-01 — Benchmark dialog dismiss-button pass (2026-07-28)

## Why the scope changed from the ticket

`MODALS_SETTINGS_TICKETS.md`'s MS-01 assumed the benchmark-scale dialogs (CPI, GDP, Wages,
Unemployment, Treasury, Housing/Bonds/Stocks) were still opened via bare
`new AlertDialog.Builder(...)` with hardcoded `Color.parseColor` rows, and proposed building a
new `BenchmarkScaleSheet` component to consolidate them.

Phase 1 exploration (grep across `ui/fragments/`, `ui/MainActivity.java`, and `res/layout/`)
found that migration already happened in an earlier batch:

- Every benchmark dialog (`dialog_cpi_status.xml`, `dialog_gdp_status.xml`,
  `dialog_wages_status.xml`, `dialog_treasury_3m_status.xml`, `dialog_unemployment_status.xml`,
  `dialog_mortgage_status.xml`, `dialog_vix_status.xml`) and `dialog_fed_funds_history.xml`
  are already opened via `MetricBottomSheet.show(...)`, not `AlertDialog.Builder`. Zero
  `AlertDialog.Builder` hits remain in `ui/fragments/`.
- Overview's KPI cards (`DashboardFragment.wireCardDialog`) already call the same
  `R.layout.dialog_*_status` resource and the same `MetricBottomSheet.show()` as the matching
  leaf-tab fragment — they're one shared component/data source already, not two copies.
- All of those layouts already use `signal_*`/semantic color tokens. Zero hardcoded hex colors
  anywhere in `res/layout/dialog_*.xml`.
- Housing/Bonds/Stocks never had their own benchmark dialogs (`dialog_housing_status.xml` /
  `dialog_bonds_status.xml` / `dialog_stocks_status.xml` don't exist); the real equivalents are
  `dialog_mortgage_status.xml` and `dialog_vix_status.xml`, already on the same pattern.
- `dialog_fed_funds_history.xml` (called out in MS-02 as "never got a look") already uses
  `MetricBottomSheet.show()` too.

So building a new `BenchmarkScaleSheet` would have duplicated `MetricBottomSheet` for no
behavioral gain. Confirmed this with the user and scoped down to the one piece of MS-01 that
was still real: **every one of these dialogs ends its content in a bare gold "DISMISS"
`TextView`, not a real button, and has no accessibility label** (the MS-05 concern, same root
cause).

## What actually changed

- **`res/values/themes.xml`** — added a `BenchmarkDismissButton` style (outlined
  `MaterialButton`, gold stroke/text, matches the dark navy dialog background) next to the
  existing `SettingsSegmentButton`/`SettingsDestructiveButton` styles.
- **8 layout files** — replaced the bare `TextView` labeled "DISMISS" with a real
  `com.google.android.material.button.MaterialButton` using that style, keeping the same
  `@+id/btnClose` (so `MetricBottomSheet.show()`'s `content.findViewById(R.id.btnClose)` /
  `setOnClickListener` wiring needs no Java changes) and same visible "DISMISS" text, and added
  `android:contentDescription="Close"` for TalkBack:
  - `dialog_cpi_status.xml`
  - `dialog_gdp_status.xml`
  - `dialog_wages_status.xml`
  - `dialog_treasury_3m_status.xml`
  - `dialog_unemployment_status.xml`
  - `dialog_mortgage_status.xml`
  - `dialog_vix_status.xml`
  - `dialog_fed_funds_history.xml` (not named in the ticket's dialog list, but same
    `MetricBottomSheet`-hosted pattern with the identical bug — fixed for consistency rather
    than leaving one mismatched instance behind)
- **Deleted `dialog_treasury_status.xml`** — confirmed via repo-wide grep that nothing
  referenced it (the live spread dialog is `dialog_treasury_3m_status.xml`); it was dead weight
  left over from an earlier pass.

No Java/Kotlin files changed. No `AlertDialog.Builder` calls, layout resource IDs, or
`MetricBottomSheet` call sites were touched.

## Follow-up — size Overview badge sheets to their content

**Ask:** the Overview KPI badge sheets (Unemployment, CPI YoY, GDP, Spread, Mortgage, VIX —
`wireCardDialog` in `DashboardFragment`) should "occupy the space it needs on the screen."

**Root cause:** `MetricBottomSheet.show()` measured the inflated content's height after layout
and compared it to 55% of screen height: under that line, it sized the sheet to content
(`fitToContents(true)` + `STATE_EXPANDED`); at or over it, the sheet opened at a fixed
`STATE_HALF_EXPANDED` (55% of screen) instead. These benchmark dialogs (5 rows + header +
dismiss button) land right around that boundary on a lot of screen sizes — so depending on the
device, the sheet either opened with dead navy space below the content, or opened with the
bottom row/dismiss button cut off the bottom edge, requiring a drag to see the rest. Neither is
"occupying the space it needs."

**Change (`ui/MetricBottomSheet.java`):** removed the 55%-threshold branch entirely. The sheet
now always sets `fitToContents(true)` + `setSkipCollapsed(true)` up front and opens straight to
`STATE_EXPANDED` (still deferred to `content.post()`, since setting state before layout is
unreliable — unchanged from before). Every `MetricBottomSheet` consumer has fixed, deterministic
content (no variable-length lists except Fed Funds history, whose `RecyclerView` sits in a
layout-fixed 400dp card), so there's no case here that benefits from a partial "peek" state —
sizing to content is strictly correct for all of them. This affects every `MetricBottomSheet.show()`
call site: the 6 Overview badges, CPI/GDP/Wages' matching leaf-tab dialogs (same layouts, same
call), and `MainActivity.showFedFundsHistory()`.
Also fixed a now-stale comment in `AiAnalystBottomSheet.java` that referenced the half-height
detent this removed.

**What to eyeball:** open each Overview badge sheet and confirm it opens already sized to its
content — no drag needed to see the dismiss button, no empty navy space below it. Same check on
the CPI/GDP/Wages tabs and Fed Funds history (Overview → Fed Funds row). Also confirm the sheet
still recedes the background and swipe-to-dismiss still works (unchanged code paths).
